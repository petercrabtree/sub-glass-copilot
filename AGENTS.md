# Repo Notes

- On each meaningful repo change, briefly consider whether `AGENTS.md` should also be updated. Only edit it when the change adds durable, high-signal guidance that will help future agents.
- Prefer Conventional Commit style messages for commits made in this repo, using a lowercase type prefix like `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, or `chore:` when it fits.
- After completing an implementation, commit the completed work by default. Follow-up changes that belong in that same unpublished unit of work should be folded in with `git commit --amend`; do not amend after the commit has been pushed.
- Do not add local, Vite, same-origin, or server-side proxy workarounds for Reddit/API access unless the user explicitly asks for a proxy-based solution.
- This is a personal project, so diagnostics and error reporting can be developer-facing and optimized for debugging rather than end-user polish.
- This app is a client-only SvelteKit SPA. `src/routes/+layout.ts` sets `ssr = false` and `prerender = false`, and `svelte.config.js` uses `@sveltejs/adapter-static` with a `200.html` fallback. Prefer browser-side solutions; do not introduce server-only assumptions unless explicitly requested.
- The codebase uses Svelte 5 runes throughout app code. Match existing patterns like `$state`, `$derived`, `$effect`, and event attributes such as `onclick`/`onsubmit` instead of older Svelte patterns.
- Core viewer behavior is route-local in `src/routes/r/[...subreddit]/+page.svelte`. Discovery and admin behavior are also mostly implemented directly in route components, so check those files first before adding new abstractions.
- UX intent for viewer chrome, mouse interactions, and hover behavior is documented in `docs/ux-interaction-spec.md`; consult it before changing reveal, mouseover, or control-surface behavior.
- Viewer display modes (`fill`, `scroll`, `masonry`, `wild`, `wild2`, `wild3`) are implemented route-locally in `src/routes/r/[...subreddit]/+page.svelte`; the active mode persists in `localStorage` under `subglass:display-mode`, and auto-next settings persist under `subglass:auto-advance-settings`.
- Viewer UI density modes (`full`, `mini`, `hidden`) also live route-locally and persist under `subglass:viewer-ui-mode`; keep hidden mode as a true single tiny reveal-control state.
- Viewer chrome should stay edge-mounted with no outer screen gaps: keep route/menu/status/queue/auto-next in one top rail, post details in a top-left panel below the rail, post actions in one bottom-left edge dock, and debug as the only optional third surface.
- Feed snapshot restore is route-local in `src/routes/r/[...subreddit]/+page.svelte` and persists into the IndexedDB `feedSnapshots` store. Preserve the behavior where reloads hydrate the same visible post first, then background-refresh without dislodging the current item.
- Local feed browsing uses `/feed/[feedname]` with durable IndexedDB `feedRecipes`, `feedRuns`, `feedRunItems`, `postSources`, `sourceStats`, and `queueEvents` stores. Keep local feeds as real feed-run queues backed by `src/lib/feed/*`; do not implement them by redirecting through `/r/...` multireddit URLs.
- Viewer dwell tracking is route-local in `src/routes/r/[...subreddit]/+page.svelte`: focused visible time records `dwell` events, soft preference changes record `dwell_score`, and the same signals feed the "why this post" UI. Keep passive dwell scoring weaker than explicit up/down ratings.
- Smart queue refill is also route-local in `src/routes/r/[...subreddit]/+page.svelte`; it estimates consumption pace from recent forward advances and preloads more listing pages before the visible queue runs dry. Preserve snapshot restore/current-item stability when changing refill thresholds.
- Roulette browsing uses `/roulette` plus `/r/<sub1+sub2>/<sort>?t=<time>&roulette=1`; selection logic lives in `src/lib/discovery/roulette.ts`, settings persist under `subglass:roulette-settings`, defaults are NSFW-centric with `/top?t=month` listings (10 subreddits, 25 images, `nsfwMode: 'only'`), liked/new/random settings are a relative selection mix under the subreddit-count total, and up/down post ratings update subreddit preference weights.
- Video auto-next is playback-aware: it resets from the current played position, honors the configured play count with a 5s minimum, and must only advance on a loop boundary so playback is never cut off mid-video. The fill-mode `MediaViewer` is keyed per media/item, and its internal reset logic must stay idempotent to avoid Svelte effect loops.
- Embedded `external_video` items do not expose reliable cross-origin playback completion events in this client-only app, so auto-next should stay disabled for iframe fallbacks instead of using the image timer. Redgifs items are first enriched browser-side through `src/lib/media/redgifs.ts`; when direct MP4 metadata resolves, they are promoted to native `video` media so normal playback-aware auto-next can apply. If the Redgifs API is blocked or missing a playback URL, preserve Reddit's `preview.reddit_video_preview` MP4/duration fallback as native video when available. The Redgifs GIF metadata endpoint is CORS-limited, so the adapter only attempts known-good localhost origins by default and falls back quietly elsewhere.
- Persistent app state lives in IndexedDB via `src/lib/db/store.ts`. The main stores are `subreddits`, `posts`, `media`, `events`, `adjacency`, `cache`, and `feedSnapshots`; admin import/export operates on that full local dataset and import is intentionally destructive.
- Subreddit availability is cached on `SubredditRecord` in IndexedDB (`availabilityStatus`, `availabilityCheckedAt`, and related detail fields). Hard-unavailable statuses such as banned/private/quarantined/not-found should be excluded from roulette and automatically removed from incoming viewer bundles; rechecks should go through the shared profile scan manager/UI rather than a separate request path.
- Browser-managed image caching now lives in `src/service-worker.ts`, with registration in `src/lib/service-worker/register.ts` and debug controls on `src/routes/admin/+page.svelte`. It is intentionally enabled during normal local dev, so preserve easy cache reset/worker reset workflows when iterating. Keep it conservative: cache image requests in Cache Storage, leave videos on the normal network path so browser range/streaming behavior stays intact, and avoid moving media bytes into IndexedDB unless the user explicitly asks for that tradeoff.
- Video preloading is browser-native rather than service-worker-managed: route-local planning in `src/routes/r/[...subreddit]/+page.svelte` feeds hidden `<video preload="auto">` elements in `src/lib/components/VideoPreloadPool.svelte`, and queue UI surfaces the resulting video warm/cache state. Preserve range/streaming behavior and keep video bytes out of Cache Storage/IndexedDB unless explicitly requested.
- Reddit access is implemented as direct browser fetches to `https://old.reddit.com/.../.json` in `src/lib/transport/reddit.ts`, with rich developer-facing error objects, local debug state, priority scheduling that keeps interactive listing/media loads ahead of background profile scans, separate interactive/background pacing timers, and shared client-side cooldown handling for explicit "too fast" responses such as 420/429, `Retry-After`, or exhausted `x-ratelimit-*` budgets. Preserve detailed diagnostics and same-request retry behavior when changing fetch behavior; keep CORS-masked/network-error backoff scoped to the priority that triggered it so auto-scan waits do not block feed loads.
- Dev diagnostics matter in this repo: `src/lib/dev/error-reporter.ts` forwards browser `console.error`, `window.error`, and `unhandledrejection` events to the Vite dev server endpoint defined in `vite.config.ts`. Avoid removing or bypassing that workflow casually.
- Adjacency/discovery behavior depends on extracting `r/...` mentions and crosspost relationships into local graph edges in `src/lib/adjacency/extract.ts`; subreddit profile fetch/extract logic lives in `src/lib/discovery/subreddits.ts`, prioritized scan scoring lives in `src/lib/discovery/scan-priority.ts`, and the shared background/manual scan queue and UI status live in `src/lib/discovery/profile-scan-manager.svelte.ts` plus `src/lib/components/ProfileScanStatus.svelte`. If discovery seems off, inspect extraction, profile scan status, priority reasons, the scan manager queue, and local data before changing ranking.
- Use Bun for the default workflow (`bun install`, `bun run dev`, `bun run check`, `bun run build`). `bunfig.toml` sets `[run] bun = true` so `bun run` aliases Node-based package bins to Bun and avoids stale system Node issues with Vite/SvelteKit. `bun run check` is the main validation command, and there is currently no dedicated automated test suite.
- When adding or updating dependencies, prefer `bun add`, `bun add -d`, `bun remove`, and `bun install` so `bun.lock` stays authoritative. Avoid `npm install` in normal repo work unless the user explicitly asks for npm.
- The user's normal dev server is usually already running on `127.0.0.1:5173`; check for an existing server before starting one, and do not start a new dev server unless none is running or the user explicitly asks for a separate server. Keep `127.0.0.1:5173` clean: do not start screenshot, smoke, or mock-data runs on that port, and do not run it with `VITE_SUBGLASS_REDDIT_BASE_URL=/__mock/reddit`. Use an isolated port/profile such as the headless smoke default `127.0.0.1:4173` for agent screenshots only when a separate run is actually needed.
- The headless smoke workflow defaults to mocked Reddit data, but it also supports an explicit live mode. Use `bun run smoke:headless` for the snapshot-backed mock run, `bun run smoke:headless:live` to hit real Reddit responses, and `bun run smoke:fixtures:refresh` whenever the default smoke source changes so `dev/generated-smoke-fixture.json` stays aligned with the live target.
